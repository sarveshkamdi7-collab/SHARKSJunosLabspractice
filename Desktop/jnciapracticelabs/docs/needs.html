1. Purpose of this document

This document stores all the needs stated by the project owner for completing the JNCIA-Junos Practice Lab project, together with the concrete acceptance details that those needs imply. It also pins down the exact Junos OS look of prompts, commands and command output that every simulated device must reproduce. A companion document (Features Implemented) tracks progress against these requirements.

2. Product vision

A browser-based practice lab for JNCIA-Junos certification study: a small multi-router and switch topology with fully simulated Junos OS CLI devices plus end hosts. The lab runs on the local machine with a simple Node.js server; no real Junos OS images, VMs, licenses or GNS3 installation are required. Candidates practice the JNCIA-Junos syllabus operations on an interface that looks and behaves like GNS3 with Juniper routers.

5. GNS3-like interface requirements (R-09..R-12)

5.1 Shell (window chrome)

  • Menu bar: File, Edit, View, Simulation, Tools, Help.
    File = New project / Save / Reset lab; View = zoom helpers, show grid, show link labels, topology summary; Simulation = Start/Stop/Reload all nodes; Help = About / shortcuts.
  • Toolbar in GNS3 style: new/open/save project, snapshot, drawing tools (rectangle, ellipse, line, text note), fit view, zoom in/out/reset, grid toggle, link labels toggle, console connector, quit + start-all / stop-all / reload-all node buttons.
  • Status bar: "Ready", zoom percent, node count, project name.

5.2 Topology canvas

  • Dark GNS3-like canvas; draggable router icons (R1, R2, R3), switch icon (SW1) and VPCS PC icons (Host-A, Host-B), each with a device label beneath, and a colored status dot (running / stopped) derived from node state.
  • Straight link lines between node icons; optional reversible link/subnet labels (10.0.12.0/30, 10.0.23.0/30, VLAN 10 trunk link).
  • Zoom & pan; grid overlay toggle; fit-to-view button.
  • Node context menu (GNS3-like items): Start, Stop, Reload, Console (opens a console window tied to the node).
  • Double-click node opens its console (authentic GNS3 behavior).

5.3 Console windows / console manager

  • Floating, draggable, resizable black terminal windows titled like R1 - telnet://127.0.0.1:5000; window title includes device name and telnet-style port.
  • Console Manager panel tracks all open consoles with ports, and can open the consoles for devices not yet connected.
  • Console of a stopped node shows telnet refusal (can't open a connection...).
  • Terminal behavior: typed echo on the prompt line, tab completion, ? completions listing, command history (up/down), key paging via space / b / q on ---(more)​---, Ctrl+C to abort, config-mode prompt includes the [edit ...] block header.

5.4 Right dock: Topology Summary + Servers Summary

  • Topology summary lists each node with expandable link entries like Link 1: ge-0/0/0 (R2 ge-0/0/0).
  • Servers summary lists the lab server (local: http://localhost:3000) and its running state.

6. CLI command scope (JNCIA-Junos syllabus surface)

6.1 Operational mode

Required command families (all output exact per Section 4):

  • Diagnostics: ping, traceroute, monitor interface;
  • Inventory/state: show interfaces (terse / brief / media / detail / statistics), show lldp neighbors, show arp, show vlans, show ethernet-switching table, show spanning-tree bridge/interface;
  • Routing: show route (+ exact / detail / extensive / protocol

    ), show route summary, show route forwarding-table;

  • Protocols: show ospf neighbor/interface/database/route/overview/statistics, show bgp summary/neighbor;
  • System: show version, show system uptime/commit, show chassis hardware/routing-engine/fpc pic-status/alarms/environment, show log messages, show configuration;
  • Administration: configure, request support information, request system reboot, start shell, file list|show, cross-device ssh/telnet, clear subcommands, set cli screen-length, exit|quit.

6.2 Configuration mode

Candidate model with / semantics, levels via edit/top/up/exit, statements set / delete / deactivate / activate / rename / copy / annotate, displays show, show | compare [rollback n], show | display set|xml|json, commits commit / commit check / commit confirmed / commit and-quit / commit comment "...", rollback [n], show system commit, run , status.

8. Devices other than Junos (R-08)

End hosts must behave like VPCS consoles, not like Junos: prompt Host-A>, VPCS-style ping / trace output, show / show ip / show arp, clear, gateway behavior, and quit. The lab engine must still carry their traffic consistently with the Junos side (ping Host-A from R1 works over the bridged VLAN; ping across VLANs is routed by SW1's irb interfaces).
