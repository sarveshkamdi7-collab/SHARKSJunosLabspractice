2.2 Junos configuration database (config tree engine) IMPLEMENTED

public/js/junos/db.js implements the heart of real Junos configuration handling:

  • In-memory hierarchical configuration tree exactly shaped like Junos config (statement names, value lists, ordered children) with identity containers (unit, address, interface, route, area, neighbor, term, filter, ...) and leaves that carry values (host-name, description, next-hop, peer-as, ...).
  • Core mutation primitives: set (incl. bracketed multi-values like members [ a b ]), delete (statement or single value, auto-cleanup of empty leaves), deactivate / activate (typical Junos inactive: marker behavior), annotate (stores /* comment */ annotations).
  • Brace-notation rendering faithful to real Junos: correct 4-space indentation chains, inactive: ge-0/0/2 { ... } headings, embedded comments (/* SPARE */ ge-0/0/2 { ... }), quoted values when needed, semicolons and nested braces exactly as Junos prints them in show/show configuration.
  • Set-notation rendering (candidate & committed, active-only option) for | display set output; proper quoting (set system description "LINK TO R2").
  • show | compare diff engine (compareTrees): real Junos-style output with [edit ...] headers and + / - / ! line markers, subtree additions/deletions, value-level additions/deletions, and deactivation shown as ! lines. Includes tree-equality checks (with and without the inactive marker) as used by the engine.
  • Data utilities used across the lab: tree cloning, subtree lookup by path.

2.3 Lab inventory & baseline configurations IMPLEMENTED

public/js/junos/model.js defines the complete practice topology and every device's factory baseline Junos configuration as Junos set statements:

  • R1 / R2 / R3 — MX240 routers, Junos 20.4R2-S2.1, deterministic serials, configured with system (host-name, time-zone UTC, ssh v2/root-login deny/limit), interface addressing (transit 10.0.12.0/30, 10.0.23.0/30; lo0 1.1.1.1–3.3.3.3/32; fxp0 mgmt 192.168.1.x), disabled spare ports with SPARE descriptions, routing-options (router-id, static default on R1, static discard on R3), OSPF area 0.0.0.0 with passive lo0, and internal BGP group PEERS (65000, loopback-based peers).
  • SW1 — authentic EX-series shape: EX4300-24T, 24 ports, family ethernet-switching access/uplink ports with vlan members, irb.10 / irb.20 SVIs, vlans staff(10) / guest(20) with l3-interface, me0 management port, and protocols rstp interface all.
  • Topology array (R1–R2, R2–R3 routed; R1–SW1 L2) and Host-A/Host-B VPCS endpoints (switch port + VLAN + IP) used by every downstream simulation.

2.4 Runtime state derivation (the "network" inside the lab) IMPLEMENTED

public/js/junos/derive.js turns committed configs + the topology into consistent, Junos-like device state used by every console command — the same way real routers derive operational state from configuration:

  • Interfaces inventory: configured and unconfigured ports (spare ge-0/0/x ports generated for realism), deterministic Interface index / SNMP ifIndex / Generation, MACs built from a stable hash (02:xx:xx:xx:xx:xx), admin/link flags from disable statements and peer port state, last-flapped from boot times.
  • Subnets / units: parsed family inet / inet6 / ethernet-switching addresses, VLAN membership lists, interface-mode (trunk/access), per-unit MTUs.
  • Route table model with real Junos protocol tags and preferences: Direct/0, Local/8, Static/5, OSPF/10, including next-hop/discard/reject static modes, correct active/non-active (* best-path) selection, and route age provenance.
  • Layer-2: VLAN bridging domains from switch config + L2 links; IRB link state tied to l3-interface references; host ports derived from VLAN membership; realistic (EX) MAC address table and STP (RSTP) bridge/role model.
  • OSPF: adjacency detection restricted to real same-subnet, non-passive, up interfaces; neighbor tables (Full state, dead time, priority 128, neighbor addresses), Router LSAs (seq/age/cksum/len with per-router values) and per-multiaccess-net LSAs, plus Dijkstra SPF over the actual adjacencies to build OSPF routes with hop costs and validated next-hops.
  • ARP & LLDP: routers learn neighbors' MACs on shared subnets (including SVI/uplink bridging through the switch), and LLDP neighbor lists are derived from physical links with real chassis IDs and port info.
  • BGP: session state machine derived both ways (peer must be reciprocally configured): Establ with packet counters/uptime, Active, or Idle when prerequisites (peer config, AS, route, local-address) are missing — exactly the states show bgp summary would display.
  • Ping/traceroute resolution engine: source-address selection (explicit source check, egress-interface choice), longest-prefix route matching, hop-by-hop path walk including no-route / discard / no-host / loop outcomes — this drives authentic ping/traceroute results.

3. Preserved exactness guarantees (already enforced by the engine)

  • Protocol tags and preferences appear exactly as Junos prints them: [Static/5], [Local/8], [OSPF/10], [Direct/0].
  • Active-route marking, + = Active Route, - = Last Active, * = Both legend support, and OSPF event ages/seq numbers derive from stable device state (uptime, commit count).
  • Peer states render with the exact Junos spelling: Establ, Active, Idle; OSPF neighbor Dead time in 00:00:35 form; priorities 128.
  • Loopback routes show as /32 per-interface Local via style entries.
  • show | compare headers use [edit ...] scopes and per-line +/-/! markers exactly like Junos diffs.
